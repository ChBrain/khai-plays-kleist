# Management Order: Set RELEASE_TOKEN

## Direction

The house's changeset wiring is complete and identical to the Buechner house —
`release.yml`, `.changeset/config.json`, and the `version` / `release` scripts
all match. But every run of the release workflow has failed: the checkout step
asks for `secrets.RELEASE_TOKEN` and gets nothing (`Input required and not
supplied: token`), because the secret was never set. So the changesets sitting
on `main` (the hardening, the prettier ignore, the rider sync, order 260609_1)
have no Version Packages PR to consume them, and the house publishes nothing.
khai-stage names the `RELEASE_TOKEN` secret as a handoff the generator cannot
perform — a secret lives in repository settings, off-stage and beyond the
Theatre Manager's tools. The Choregos direct that the token be set so the house
versions and publishes like Buechner.

## Orders

1. The human (who alone holds deploy authority) shall create a fine-grained or
   classic PAT with **Contents: write** and **Pull requests: write** on this
   repository — the rights the release workflow needs to push the
   `changeset-release/main` branch and tags and to open the Version PR.
2. The human shall add it as the repository secret **`RELEASE_TOKEN`**.
3. With the secret in place, the release workflow shall be re-run (or the next
   push to `main` shall trigger it) so the Version Packages PR opens, bumps the
   version, and writes the `CHANGELOG`.

## Implementation

Create the PAT (GitHub → Settings → Developer settings → Personal access
tokens), then add the secret:

    gh secret set RELEASE_TOKEN --repo ChBrain/khai-plays-kleist

or **Settings → Secrets and variables → Actions → New repository secret**, name
`RELEASE_TOKEN`. Then re-run the latest failed `release` run, or merge any PR to
`main`. The first Version Packages PR will bump `0.0.0` and consume the pending
changesets.

This order is a rider committed alone, so the guard homes it to the `governance`
lane.
